### Key Architectural Shifts

* **`meta_builder` Owns the Workflow:** The Application Builder provides the unified API and interfaces for developers. It handles request intake, governs build states, and produces generated application components.


* **BCR as the Passive/Intelligent Storage Sub-component:** BCR exposes atomic registry APIs (`store`, `resolve`, `fetch_by_urn`, `update_lifecycle`). `meta_builder` queries BCR to retrieve standard base blueprints (e.g., global or industry templates), calculates the resolved AST within its own engine, and pushes final registered bundle metadata back to BCR for safe keeping.


* **Validation Resides in the Engine:** The logic enforcing domain governance (such as ensuring a Provider delta doesn't override a `FINAL` immutable attribute) runs inside `meta_builder`’s validation engine during the pipeline execution.
