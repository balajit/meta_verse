**Phase 2 Architectural Design: Namespace Registry & Inheritance Engine**

Phase 2 transitions MetaBuilder from a static DAG compiler into a polymorphic execution platform. It introduces multi-tenant hierarchy resolution, differential overriding, entity FSM state mechanics, and foundational platform manifests (Learning Platform and Commerce Platform).

---

**High-Level Architecture & Resolution Pipeline**

```
 [ Base / Parent Manifests ]     [ Child Variant / Overrides ]
              │                               │
              └───────────────┬───────────────┘
                              │
                              ▼
        ┌──────────────────────────────────────────┐
        │       1. Namespace Resolution Engine     │

        └─────────────────────┬────────────────────┘
```

### **Core Functional Components**

#### **1. Namespace Resolution Engine**

Resolves entity definitions and workflow variants across a three-tier inheritance hierarchy: `global` $\rightarrow$ `industry` (LOB) $\rightarrow$ `custom` (Tenant/Channel).

* **Namespace Tree Resolver:**
* Computes the explicit resolution path for any target query.
* *Resolution Order:* `custom:{tenant_id}:{channel}` $\rightarrow$ `industry:{lob_id}` $\rightarrow$ `global:default`.


* **Inheritance Resolver & Fallback Chain:**
* Traverses parent pointers (`extends: <namespace:version>`) sequentially.
* Prevents circular dependency chains using depth-first graph traversal and visited sets.


* **Namespace Cache Guard:**
* Caches fully resolved inheritance graphs in-memory to prevent re-parsing base models during hot execution paths.



---

#### **2. Polymorphic Merge Engine (Differential Overrides)**

Handles dynamic schema and DAG merging when a child manifest overrides a parent.

* **Structural Deep Merger:**
* Merges JSONB/Pydantic schemas using strict inheritance semantics.
* Supports field additions, type specialization, and constraint tightening (e.g., making optional fields required in `custom`).


* **Graph Topological Delta Compiler:**
* Evaluates task node modifications (`ADD`, `REPLACE`, `DISABLE`, `WRAP`).
* Re-validates DAG topological integrity after applying delta transformations to ensure no cycles are introduced.


* **Contract Inheritance Checker:**
* Enforces contravariance on task inputs and covariance on task outputs during inheritance overrides.



---

#### **3. Entity FSM State Engine**

Manages domain entity lifecycle transitions independently of workflow step execution, ensuring data entities progress safely through allowed states.

* **Lifecycle State Transition Guard:**
* Enforces state machine rules (e.g., `DRAFT` $\rightarrow$ `REVIEW` $\rightarrow$ `PUBLISHED` $\rightarrow$ `ARCHIVED`).
* Uses optimistic lock tokens to block invalid state transitions.


* **Pre/Post-Transition Hook Registry:**
* Triggers event side-effects (telemetry, validations, downstream notifications) upon entering or exiting specific lifecycle states.


* **Entity State Persister:**
* Maintains an audit log of state histories, actor citations, and payload snapshots per state change.



---

#### **4. Dynamic Manifest Hydrator & Manifest Realization**

Loads, validates, and materializes base platform structures.

* **LP (Learning Platform) Manifest Realizer:**
* Compiles base specifications for content ingestion, parsing, vectorization, and assessment generation pipelines.


* **CP (Commerce Platform) Manifest Realizer:**
* Compiles base specifications for catalog ingestion, price indexing, inventory validation, and order fulfillment workflows.


* **Versioned Schema Serializer:**
* Persists fully compiled, polymorphic manifests to PostgreSQL with deterministic version signatures (`manifest_hash`).



---

### **Namespace & Manifest Resolution Design**

#### **Resolution Algorithm**

When a workflow execution is triggered for `tenant="acme"`, `lob="retail"`, and `channel="mobile"`:

1. **Lookup Search Path:**
`custom:acme:mobile` $\rightarrow$ `industry:retail` $\rightarrow$ `global:default`.
2. **Fetch Tree Nodes:** Retrieve all manifest snapshots along the chain from database/registry.
3. **Linearize & Merge:**
* Start with `global:default` AST.
* Apply `industry:retail` deltas.
* Apply `custom:acme:mobile` deltas.


4. **Compile & Register:** Produce an immutable, compiled DAG manifest runtime snapshot.

### **Entity FSM Lifecycle Transition Design**

#### **Allowed State Transitions**

```
[ DRAFT ] ────────► [ UNDER_REVIEW ] ────────► [ PUBLISHED ]
   │                       │                        │
   │                       ▼                        ▼
   └─────────────────► [ REJECTED ] ──────────► [ ARCHIVED ]

```

#### **FSM Validation Mechanics**

* **Guard Matrix:** A matrix mapping `(current_state, target_state) -> List[GuardCondition]`.
* **Atomic State Updates:**
```sql
UPDATE entity_instances
SET state = :target_state, version = version + 1
WHERE id = :entity_id AND state = :current_state AND version = :expected_version;

```

### **Proposed Database Schema Additions for Phase 2**

* **`meta_namespaces` Table:** Stores registered namespaces (`global`, `industry`, `custom`) and their parent references.
* **`meta_entity_definitions` Table:** Versioned registry of domain entities, their base fields, and their polymorphic extensions.
* **`meta_entity_fsm_rules` Table:** Defines valid `(from_state, to_state)` pairs, permissions, and validation handlers.
* **`meta_entity_instances` Table:** Tracks live entity records, current lifecycle state, active lock tokens, and JSONB payload snapshots.

Google Design:
Here is a breakdown of open-source frameworks, libraries, and design standards suitable for each Phase 2 core component.

---

**1. Namespace Resolution Engine**

This component requires hierarchical lookup, fallback chains, and graph dependency tracking.

* **NetworkX (Python):** Ideal for constructing the directed inheritance tree (`global` $\rightarrow$ `industry` $\rightarrow$ `custom`). It handles cycle detection, topological sorting, and parent-child ancestor traversal natively.


* **Open Policy Agent (OPA / Rego):** Can be embedded to evaluate namespace resolution rules, dynamic tenant scoping, and context-aware fallback paths based on runtime attributes (`tenant_id`, `channel`, `lob_id`).


* **Hierarchical Configuration Libraries (e.g., Dynaconf / Hydra):** Provide built-in inheritance chains, cascading layer resolution, and environment/tenant overrides out of the box.

---

**2. Polymorphic Merge Engine (Differential Overrides)**

This component handles AST transformations, structural JSON/Schema merging, dynamic DAG patching, and contract verification.

* **JSON Patch (RFC 6902) & JSON Merge Patch (RFC 7396) Implementations (e.g., `jsonpatch` / `jsonmerge` in Python):**
* `jsonmerge`: Provides rule-based structural schema merging (e.g., `ARRAY_MERGE`, `STRATEGY_OVERWRITE`, `$patch`).
* `jsonpatch`: Standardized format for granular operations (`ADD`, `REPLACE`, `REMOVE`) across dynamic task nodes and entity fields.




* **Pydantic V2 (Core Generics & Dynamic Types):** Native support for model inheritance, schema specialization, and dynamic model generation (`create_model`) to enforce type contravariance/covariance dynamically.


* **Apache Hamilton & `h_schema`:** Validates runtime payload signatures, node dependency overrides, and contract inheritance across DAG transformations.



---

**3. Entity FSM State Engine**

This component enforces lifecycle transitions, optimistic locking, transition guards, and audit history independently of task execution.

* **Transitions / `python-statemachine`:**
* Lightweight Python FSM libraries supporting state transition callbacks (`pre_transition`, `post_transition`), state guards, and error handling.




* **Temporal.io (or Automata / PostgreSQL FSM Extensions):**
* Provides durable state machine execution, deterministic state persistence, and event-driven transition guards for enterprise lifecycle workflows.




* **SQLAlchemy + PostgreSQL (`TIMESTAMPTZ`, JSONB, Optimistic Locking):**
* Standard stack for atomic database updates using version tokens (`version = version + 1`) and transition audit logging.





---

**4. Dynamic Manifest Hydrator & Manifest Realization (LP & CP Platforms)**

This component handles YAML parsing, schema compilation, hash signatures, and persistence.

* **Ruamel.yaml / PyYAML:** For lossless, high-performance parsing of declarative YAML manifests.


* **JSONSchema (Draft 2020-12):** Validates raw merged structures against platform meta-schemas prior to Pydantic instantiation.


* **Hashlib / Canonical JSON (jcs):** For generating deterministic, cryptographic hash signatures (`manifest_hash`) for versioned persistent records.
