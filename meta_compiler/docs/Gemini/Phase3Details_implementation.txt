The production-grade directory structure for the **Meta-Builder Brain** (`meta_builder_brain`) isolates ingestion pipelines, LLM synthesis workflows, policy guardrails, and dynamic schema compilation into distinct runtime packages.

```text
meta_builder_brain/
├── docker/
│   ├── Dockerfile
│   └── opa/
│       └── config.yaml           # OPA sidecar configuration
├── config/
│   ├── settings.py               # Application settings & OpenBao secrets fetcher
│   └── policies/
│       └── fsm_inheritance.rego  # Rego policies enforcing inheritance & state rules
├── ingestion/
│   ├── __init__.py
│   ├── router.py                 # FastAPI webhook and REST ingestion gateway
│   ├── document_parser.py        # PyMuPDF & Docling text/PDF hierarchical partitioner
│   ├── web_scraper.py            # Playwright headless browser pool for web standards
│   └── schema_parser.py         # OpenAPI v3 & JSON Schema AST extractor
├── synthesis/
│   ├── __init__.py
│   ├── agent.py                  # Single-agent harness (Hermes) orchestrator
│   ├── mcp_server.py             # Model Context Protocol tool bindings for sub-schemas
│   ├── llm_client.py             # Anthropic/Qwen client with asyncio semaphore limits
│   └── prompts/
│       ├── system_prompts.py     # Schema extraction & FSM lifecycle instructions
│       └── json_schemas.py       # Pydantic-backed JSON schema constraints
├── validation/
│   ├── __init__.py
│   ├── pydantic_models.py        # Strict Meta-Model manifest validation models
│   ├── retry_loop.py             # Error-trace capture & feedback prompt generator
│   └── opa_evaluator.py          # Asynchronous OPA sidecar HTTP client
├── compiler/
│   ├── __init__.py
│   ├── metaclass_builder.py      # Dynamic Python metaclass ORM & model generator
│   └── store.py                  # SQLAlchemy session manager & PostgreSQL compiler
├── main.py                       # Application entrypoint & worker event loops
└── docker-compose.yml            # Multi-container orchestration mesh

```

**Directory & Component Descriptions**

**Ingestion Layer (`ingestion/`)**

* `router.py`: Handles incoming webhook payloads, raw RFC uploads, and OpenAPI endpoint links via FastAPI async routes.


* `document_parser.py`: Integrates PyMuPDF for structural PDF merging and Docling to partition text and tables into clean markdown trees.


* `web_scraper.py`: Manages containerized Playwright browser instances to render and extract dynamic standards documentation.


* `schema_parser.py`: Parses hosted OpenAPI/Swagger specifications and raw JSON Schemas directly into flattened property graphs.

**Synthesis Layer (`synthesis/`)**

* `agent.py`: Executes the single-agent execution flow for two-pass entity and state machine generation.


* `mcp_server.py`: Exposes Model Context Protocol tool tools allowing the agent to dynamically look up existing `global/` namespace manifests during pass 2.


* `llm_client.py`: Wraps outbound SDK calls with `asyncio` semaphores to regulate outbound token consumption and concurrency.


* `prompts/`: Stores system prompts and enforced JSON schemas for structured model generation.



**Validation & Guardrails (`validation/`)**

* `pydantic_models.py`: Defines the strict schema primitives for manifest structure validation.


* `retry_loop.py`: Intercepts Pydantic `ValidationError` traces and synthesizes correction prompts for automated LLM retry iterations.


* `opa_evaluator.py`: Sends synthesized manifests to the localized Open Policy Agent sidecar to verify Rego compliance before namespace registration.



**Runtime Storage & Compiler (`compiler/`)**

* `metaclass_builder.py`: Uses custom Python metaclass patterns to dynamically construct SQLAlchemy ORM models from validated manifests at runtime.


* `store.py`: Persists dynamic database migrations, manifest revisions, and compiled task graphs into PostgreSQL.



**Configuration & Infrastructure (`config/`, `docker/`)**

* `settings.py`: Fetches runtime parameters and authenticates against the OpenBao server container to fetch API keys and database credentials.


* `fsm_inheritance.rego`: Rego policy file enforcing that child namespaces do not mutate immutable primary key definitions or base attributes.


Gemini Thoughts:  About gaps in phase 1 and phase 2.

The current `meta_polymorph` namespace resolution implementation operates as an isolated in-memory utility rather than integrating with the architecture defined in Phase 1 and Phase 2.

**1. Bypassing Validation & Policy Enforcement (`validation/`)**
* **Inline OPA Client**: `FallbackChainEvaluator` implements an ad-hoc inline `try/except` HTTP check instead of leveraging the central `validation/opa_evaluator.py` sidecar client.
* **Unused Rego Policies**: Policy checks verify generic boolean `allow` flags rather than executing the governance rules defined in `config/policies/fsm_inheritance.rego` to enforce primary key and state immutability.
* **Missing Schema Validation**: `NamespaceNode` creation and context payloads bypass the strict manifest validation schemas defined in `validation/pydantic_models.py`.

**2. Decoupled from Storage & Dynamic Compilation (`compiler/`)**
* **No Database Synchronization**: `TreeResolver` builds ancestor trees strictly from in-memory dictionary states instead of querying persisted namespace revisions from PostgreSQL via `compiler/store.py`.
* **Unused Metaclass Builder**: The output `ResolutionPath` returns a static array of node IDs (`["acme_tenant", "learning_platform", "global_root"]`), but never passes this hierarchy into `compiler/metaclass_builder.py` to dynamically assemble active SQLAlchemy ORM models.

**3. Omission of Agent & MCP Capabilities (`synthesis/`)**
* **Unregistered MCP Tools**: `synthesis/mcp_server.py` was built to allow tools to look up `global/` namespace manifests dynamically, but `TreeResolver` is not bound as an MCP tool for `synthesis/agent.py`.
* **Bypassed LLM Orchestrator**: Entity resolution and fallback handling rely on static graph traversals rather than utilizing the single-agent harness (`synthesis/agent.py`) or structured prompt pipeline (`synthesis/prompts/`) for dynamic schema synthesis.

**4. Ingestion Pipeline Disconnect (`ingestion/`)**
* **Manual Data Structures**: Nodes are manually instantiated in unit tests rather than being extracted and populated automatically from OpenAPI specs or JSON Schema ASTs via `ingestion/schema_parser.py` or raw docs via `ingestion/document_parser.py`.

**5. Infrastructure & Secrets Isolation (`config/`)**
* **Standard Settings Bypass**: Configuration management uses direct attributes on a local settings object rather than pulling authenticated runtime keys and OPA parameters through `config/settings.py` via OpenBao.

Gemini Thoughts:
The current implementation of Phase 3 treats namespace resolution as a standalone, in-memory utility, completely disconnected from the multi-package core established in `meta_builder_brain`. To achieve modular architectural coherence, Phase 3 must refactor its execution flow to directly leverage the foundational components built in Phases 1 and 2.

**Validation & Guardrail Integration**

* **Centralize Policy Checks**: Replace ad-hoc, inline HTTP checks with `validation/opa_evaluator.py`. OPA evaluations must validate compliance against `config/policies/fsm_inheritance.rego` to enforce primary key and state immutability across parent-child tiers.


* **Enforce Strict Schema Contracts**: Ingested nodes and context objects must be validated through `validation/pydantic_models.py` instead of relying on unvalidated, generic dataclasses. Invalid shapes should feed into `validation/retry_loop.py` for automated trace capturing.



**Compiler & Storage Integration**

* **Database-Backed Graph Resolution**: Deprecate the in-memory dictionary inside `TreeResolver` and query persisted, versioned manifest chains stored in PostgreSQL via `compiler/store.py`.


* **Dynamic Metaclass Compilation**: Pass the resolved ancestor chain output directly into `compiler/metaclass_builder.py`. This builds live, dynamically inherited SQLAlchemy ORM models at runtime based on the resolved fallback order.



**Synthesis & MCP Tool Registration**

* **Expose Resolution via MCP**: Expose tree resolution methods as active Model Context Protocol tools in `synthesis/mcp_server.py`. This enables the single-agent harness in `synthesis/agent.py` to inspect parent and global namespace manifests during pass-2 entity generation.


* **Managed Token Concurrency**: Route any schema synthesis or agent fallback calls through `synthesis/llm_client.py` to utilize bounded `asyncio` semaphores and centralized Anthropic/Qwen client logic.



**Automated Ingestion & Infrastructure Setup**

* **Automated Node Generation**: Replace manual unit test node creation by feeding parsed schemas from `ingestion/schema_parser.py` and structured document trees from `ingestion/document_parser.py` directly into the tree builder.


* **Secrets & Setting Management**: Wire environment settings and OPA base URLs through `config/settings.py` so runtime credentials and API keys are fetched securely via OpenBao.
