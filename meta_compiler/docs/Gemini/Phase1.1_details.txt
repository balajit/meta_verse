### 1. Core Database State Engine (FSM Infrastructure)

Manages persistent state, idempotency checkpoints, and transition locks across task executions.

* **`lp_workflow_definitions` Table:** Versioned registry storing DAG schemas, edge routing rules, and handler bindings in JSONB format.


* **`lp_workflow_instances` Table:** Global state tracker for parent workflow runs (`PENDING`, `RUNNING`, `COMPLETED`, `FAILED`, `HALTED`).


* **`lp_task_executions` Table:** Step-level execution log capturing attempts, execution windows, error codes, and JSONB pointers to input/output artifacts (`input_ref`, `output_ref`).


* **State Transition Guard:** Atomic DB-level state machine enforcing valid transitions (e.g., `PENDING` $\rightarrow$ `RUNNING` $\rightarrow$ `COMPLETED` / `FAILED`).

### Key Architectural Frameworks by Layer

**1. Schema Compilation & Payload Contract Enforcement**

* **Pydantic V2**: Translates structural YAML specifications into validated runtime objects. It dynamically creates and validates Pydantic data schemas at runtime, ensuring that inputs and output artifacts (`input_ref`, `output_ref`) match expected types before execution.


* **JSONSchema (`jsonschema`)**: Validates raw input YAML documents directly against predefined meta-schemas (e.g., JSON Schema Draft 2020-12). It acts as an early-stage syntax guard before deeper topological graph compilation occurs.

**2. Graph Topology & DAG Validation Engines**

* **NetworkX**: Serves as the primary engine for graph verification. It ingests parsed task edge definitions, performs graph validation checks (such as Kahn's algorithm or Tarjan's strongly connected components algorithm), and rejects invalid or cyclic manifests before database persistence.


* **Rustworkx**: Provides high-performance, Rust-backed graph processing for Python. It is ideal if the platform requires validating complex multi-node graphs or high-frequency manifest compilation within sub-millisecond execution windows.
* **`graphlib.TopologicalSorter`**: Standard Python module for linearizing task node dependencies, determining parallel step execution layers, and detecting circular dependencies.

**3. Higher-Level Declarative Workflow Compilers**

* **Apache Hamilton**: Transforms declarative task graph specifications into validated, portable execution graphs. It features native data validation adapters (`SchemaValidator`, `@check_output`) that inspect data structures across pipeline nodes.
* **Dagster Core (`dagster-pipes` / `DagFactory`)**: Provides declarative workflow abstractions that separate DAG graph structures from underlying execution logic. It allows YAML specs to be compiled into static, typed execution definitions.

---

### Recommended Framework Selection for Phase 1

* **Schema Parsing & Dynamic Typing:** **Pydantic V2** combined with **`jsonschema`** for two-pass manifest parsing and artifact contract validation.


* **DAG Topology & Cycle Detection:** **NetworkX** (or standard library **`graphlib`**) for fast topological sorting and explicit cycle validation during registration into `lp_workflow_definitions`.


* **Micro-DAG Validation Wrapper:** **Apache Hamilton** for lightweight, in-memory dependency parsing and payload contract checking across task handler boundaries.

### Module Responsibilities & Core Functions

#### **1. Syntax Guard (`src/lp_compiler/guards/syntax_guard.py`)**

* **Responsibility:** Ingests raw YAML/JSON specifications and validates overall structure against static JSON Schema Draft 2020-12 rules prior to dynamic model creation.


* **Core Functions:**
* `load_meta_schema(schema_path: Path) -> dict`: Loads and caches the base validation schema from disk.
* `validate_manifest_syntax(raw_manifest: dict) -> dict`: Executes `jsonschema.validate()`, raising structured `SyntaxValidationError` on schema mismatches.





---

#### **2. Dynamic Model Compiler (`src/lp_compiler/compilers/`)**

* **Responsibility:** Translates raw dictionary structures into typed dynamic runtime Pydantic objects, enforcing validation on payload boundaries (`input_ref`, `output_ref`).


* **Core Models (`models.py`):**
* `TaskNodeSpec(BaseModel)`: Node execution metadata, task parameters, and dependency aliases.


* `ArtifactRefSpec(BaseModel)`: Pointer types for input/output schema bindings (`input_ref`, `output_ref`).


* `WorkflowManifestSpec(BaseModel)`: Global workflow definition wrapping task nodes and edge routes.




* **Core Functions (`model_compiler.py`):**
* `compile_runtime_models(validated_manifest: dict) -> WorkflowManifestSpec`: Materializes dynamic Pydantic models from raw dicts.


* `build_dynamic_artifact_schema(ref_spec: ArtifactRefSpec) -> Type[BaseModel]`: Generates dynamic Pydantic data wrappers for input/output validation at task boundaries.





---

#### **3. Topological Validator (`src/lp_compiler/validators/topology_validator.py`)**

* **Responsibility:** Construct a `NetworkX` directed graph (`DiGraph`) from compiled node dependency mappings to verify acyclic guarantees and establish execution ordering.


* **Core Functions:**
* `build_networkx_graph(manifest: WorkflowManifestSpec) -> nx.DiGraph`: Populates graph nodes and directed dependency edges.


* `assert_acyclic_topology(graph: nx.DiGraph) -> List[str]`: Evaluates `nx.is_directed_acyclic_graph()`; raises `CyclicGraphError` if execution loops exist.


* `compute_execution_order(graph: nx.DiGraph) -> List[List[str]]`: Generates topologically sorted parallel execution stages (`nx.topological_generations` or `graphlib.TopologicalSorter`).





---

#### **4. Payload Contract Checker (`src/lp_compiler/contracts/contract_checker.py`)**

* **Responsibility:** Leverages **Apache Hamilton** to build an in-memory execution graph that validates data-type compatibility across step boundaries before committing definitions to the database.


* **Core Functions:**
* `build_hamilton_driver(manifest: WorkflowManifestSpec) -> h_driver.Driver`: Compiles in-memory Hamilton node definitions with `@check_output` data validation decorators.


* `verify_node_contracts(driver: h_driver.Driver, execution_order: List[str]) -> bool`: Dry-runs type checks across graph edges to ensure upstream step output types match downstream input expectations.





---

#### **5. Database Serializer (`src/lp_compiler/persistence/db_serializer.py`)**

* **Responsibility:** Maps compiled workflow graphs into database payloads and handles async transactional inserts into target state tables.


* **Core Functions:**
* `to_db_payload(manifest: WorkflowManifestSpec, topo_order: List[List[str]]) -> dict`: Transforms verified models into versioned JSONB blobs matching DB column definitions.


* `persist_workflow_definition(payload: dict, session: AsyncSession) -> UUID`: Executes SQLAlchemy `INSERT` into `lp_workflow_definitions`, returning the global definition identifier.





---

#### **6. Pipeline Orchestrator (`src/lp_compiler/orchestrator.py`)**

* **Responsibility:** Exposes a clean, unified facade that chains Steps 1 through 5 sequentially.


* **Core Functions:**
* `compile_and_register_manifest(raw_yaml_str: str, session: AsyncSession) -> UUID`: Orchestrates the complete compilation lifecycle (Parsing $\rightarrow$ Model Compilation $\rightarrow$ Graph Validation $\rightarrow$ Contract Verification $\rightarrow$ Persistence).
